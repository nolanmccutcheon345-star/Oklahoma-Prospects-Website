# W4: automatic group enrollment and pending notifications

Stacked on PR39, exact 4be7d5db. Migration 0033 creates enrollments and a durable notification outbox. No existing request is treated as permission to auto-enroll: matching requires the new autoEnroll acknowledgement and an explicit season. The form discloses sport/age/season matching, capacity, one group appointment and the separate agreement needed for private appointments.

Submitting an intake request and publishing/editing an event invoke matching inside the same transaction as the save. Upcoming published events are processed earliest first. Open eligible requests match normalized age/season and exact sport. Row locks serialize capacity and edits. An applicant fingerprint uses normalized guardian email, player name, sport, age and season; a unique active index prevents duplicates across retry/new request IDs and multiple events. A request with no match/full capacity stays open. Legacy requests without season/acknowledgement remain for staff follow-up. Twins sharing the same name, age and guardian email require staff identity clarification; intake has no authenticated athlete ID yet.

Existing enrollments prevent lowering capacity below occupancy or changing sport/season/ages without cancellation. Event cancellation retains enrollment records, marks them cancelled and records pending notices. Changes supersede unsent older notices. Notice records contain only private recipient/player and event details, never public contact exposure. Owners can see enrollments and notice status; registration readers/player/coach/forged admin accounts cannot.

Notification delivery is NOT activated by this PR. No provider calls, real messages, Square changes or production migrations occur. Do not publish this flow as a completed notification experience until isolated delivery/retry tests and hosted migration/role/browser acceptance pass. Next: email delivery with provider idempotency, retries and isolated test-recipient restrictions; admin/private appointment confirmation. Public UI does not promise a response deadline.

Local tests use migrated disposable Postgres and cover matching, full capacity, duplicate identities/UUID retries, capacity increases/decreases, cancellation notice supersession, denied roles and concurrent applicants competing for one place. Existing account/lesson workflows also pass.
